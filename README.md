# 配速記帳 (Pace Budget)

> A personal budgeting tool that answers one question every day: at this rate, how much can I still spend per day?

大部分記帳 App 告訴你「還剩多少錢」。這個數字會騙人——月中看還有兩萬很寬裕，第 25 天就見底了。

這支工具回答的是**配速**：以今天來說，你應該花到哪、實際花到哪、差多少。

## 核心概念：進度條上的那條線

每個類別的進度條上有一條深色細線，標示「以今天來說，正常應該花到的位置」。

```
必要支出                          步調正常
[███████████████▏        |        ]
                         ↑
                 今天應該在這裡
```

條子超過細線 = 花太快。不用等到超支才知道。

首頁最大的數字是 **「接下來每天可以花 NT$X」**（可支配剩餘 ÷ 剩餘天數）——每天瞄一眼就能行動的唯一數字。

## 產品決策

### 1. 投資與消費放在同一頁，但語意相反

類別有三種類型，決定它怎麼被判讀：

| 類型 | 進度快 | 進度慢 |
|---|---|---|
| 支出 | 危險 | 正常 |
| 投資 / 儲蓄 | 達標 | 落後 |

投資類別的「已用」語意是**已投入**，花得快是好事。沒有這個區分，把投資放進同一張儀表板只會讓兩邊互相污染。

### 2. 「每天可以花」只算支出類

不把投資額度算進可支配金額。否則你會以為自己每天能花的錢比實際多——這正是預算工具最容易誤導人的地方。

### 3. 週期用發薪日起算，不用曆月

5 號領薪水，「這個月還剩多少」就該從 5 號算到下個月 5 號。

發薪日限制在 **1–28 號**：29–31 號在某些月份不存在，會讓週期長度算錯。這是刻意的功能限制，不是疏漏。

### 4. 比例必須剛好 100% 才能儲存

分配框架的定義就是把收入分完。不強制的話，這個工具會慢慢退化成一般的分類記帳。

## 內建框架

| 框架 | 分法 |
|---|---|
| 50 / 30 / 20 | 必要支出 50、想要 30、儲蓄投資 20 |
| 六個罐子 | 生活必需 55、休閒 10、教育 10、財務自由 10、長期儲蓄 10、貢獻 5 |
| 4321 | 生活 40、儲蓄投資 30、保險 20、緊急預備 10 |

也可以自己定義，上限 6 類。

## 已知限制與下一步

- **目前全手動輸入。** 自動匯入規劃走台灣電子發票載具：信用卡、行動支付、悠遊卡都能歸戶到手機條碼，現金只要結帳時報載具一樣拿得到雲端發票。銀行端沒有開放給個人的交易 API，不開發票的支出（繳費、國外、訂閱）只能靠帳單匯入。
- 匯入刻意排在類別穩定之後。資料進來卻沒有對應的類別可歸，等於白做。
- 資料存在 Claude Artifact 的資料庫（跨裝置）；**以 GitHub Pages 或本機開啟時會退回 localStorage**，只存在該台裝置。
- 首次開啟帶一組標示「範例」的預載資料，數字為佔位用，按一下即可清除。

## 技術

單一 HTML 檔，無建置流程、無框架。字型走 Google Fonts，其餘全部 inline。

配色使用經過色盲安全性驗證的分類色票（OKLab ΔE 檢查，淺色深色兩套各自選色而非反轉），每個類別同時有文字標籤，不靠顏色單獨辨識。
